# AI 协作与讲解提纲

## 给 AI 的提示词怎么逐步变清楚

1. 给目标和约束：“我要在云 GPU 上部署 DeepRacer，预算有限。先验证这是虚拟机并且 Docker 可用，不要重装驱动。”
2. 给证据：“这里是系统版本、GPU 信息、完整执行命令和错误输出。请先判断是网络、权限还是配置问题。”
3. 分阶段验收：“先跑通 hello-world，再验证容器内 GPU，成功后再部署训练组件。开始训练前让我确认自动关机时间。”
4. 给开发要求：“做一个只读奖励曲线看板，训练与评估分开显示，用 SSH 隧道访问，不开放公网端口。”
5. 给改进边界：“保留旧模型，在新副本测试速度变化；只修改一个关键变量，补充离线测试，不把未完成圈的耗时当成绩。”
6. 给备份要求：“实时同步本项目日志到电脑，密码不落盘，断线后补拉，停止同步不能影响训练。”

AI 的价值是把报错、查证、代码、测试串起来，不是只生成一段命令。关键操作需要明确授权；人负责比赛要求、预算、评估口径和最终验收。

## 经验

- 容器里有 root 不代表有宿主机权限。Docker 解包报 `unshare: operation not permitted` 与镜像下载超时不是同一种故障。
- `nvidia-smi` 成功不等于训练容器可用，GPU 透传要单独验证。
- 先跑通最小流程，再优化奖励；保留基线和可回滚副本。
- 修改动作速度不一定立即更快，转弯与路线会一起变化，继续训练也不保证自动修复一切。
- 奖励曲线用于诊断，比赛目标应通过评估完整圈率和圈速验证。
- 自动关机和本地日志先安排好，避免忘记关机及电脑重启后失去记录。

## 真实截图清单

待云主机成功开机、用户设定自动关机并授权训练后，采集：

1. 环境验证：系统版本、Docker 和容器内 GPU。无需重复安装，只展示真实验证结果。
2. 模型与配置：模型前缀、赛道、奖励/动作版本、恢复的 checkpoint（不显示凭据）。
3. 训练进行中：训练日志或新 checkpoint 写入。
4. 看板：奖励、完成率、最近评估，保留真实数据更新时间。
5. 摄像头：车辆在 re:Invent 2018 赛道运行。

截图不包含服务器密码、SSH 地址、云账户资料或临时令牌；失败过程与历史图片应明确标注日期，不冒充当前训练。截图未实际采集前不写“已完成”。
