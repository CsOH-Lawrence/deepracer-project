# DeepRacer 懒人部署指南

目标：用云端 GPU 虚拟机训练，本机浏览奖励曲线和摄像头。不是让本地电脑承担训练，也不是把 AI 装进 GPU。

整理日期：2026-10-18。基础路径参考本项目实际部署经验，并核对了文末上游脚本；**本指南尚未在另一台空白机器上逐步复装验证**。上游默认分支会变化；遇到不同输出先停下，不要连续猜命令。

## 先选对入口

- **新租的空白机器**：从第 1 步开始。
- **已经部署过，只是关机后重新开机**：直接看第 8 步。不要重跑初始化，不要重装 Docker/驱动。
- **只想看页面**：找部署者获得私有隧道或登录后的域名，不需要安装完整训练平台。

下文代码框只复制命令，不复制终端提示符 `ubuntu@...$`。每次复制一块，按回车，确认结果再继续。多行命令使用 Linux 的反斜线 `\`，不要换成 `%`。安装界面若询问重启服务，先读清楚，不要中断包管理器。

## 1. 租机器前核对这四点

1. 是可用 Docker 的 GPU **虚拟机**，不是限制 `unshare` 的普通容器。
2. 供应商镜像最好已安装 Docker、Compose、NVIDIA 驱动和 Container Toolkit；不要仅凭镜像名字判断可用。
3. 本实践配置：Ubuntu 22.04、RTX 3090、16 vCPU、约 64 GB 内存、100 GB 系统盘。不是最低要求；镜像解压和模型会占很多磁盘。
4. **先设自动关机并核对时间**。没有 GPU 资源时，实例可能无法开机；不要因此重复创建收费机器。

## 2. 登录云服务器，做最小检查

在供应商网页终端或本机 SSH 登录。下面命令在 **Ubuntu 服务器** 执行，不是在 Windows PowerShell 中执行：

```bash
cat /etc/os-release
nvidia-smi
nproc
free -h
df -h /
```

应能看到 NVIDIA 显卡和足够的磁盘余量。`nvidia-smi` 顶部 CUDA 版本是驱动支持能力，不是所有训练环境都要换成该 CUDA 版本。

```bash
sudo docker info
sudo docker compose version
sudo docker run --rm hello-world
```

看到 `Hello from Docker!` 才继续。若 Docker 没装好，按 [Docker Ubuntu 官方安装文档](https://docs.docker.com/engine/install/ubuntu/) 处理；不要在已经工作的机器上重复安装另一套 Docker。

若普通 `docker info` 报 socket 权限错误，可将当前 SSH 用户加入 docker 组，然后**断开并重新登录**：

```bash
sudo groupadd -f docker
sudo usermod -aG docker "$(id -un)"
```

重新登录后运行 `id -nG` 和 `docker info`。不要把 Docker socket 改成所有人可写；docker 组本身已有接近主机管理员的权限。`newgrp docker` 的组密码提示不是云服务器控制台密码，本指南直接用重新登录避开这一混淆。

## 3. 验证 Docker 内能使用 GPU

```bash
docker run --rm --gpus all nvcr.io/nvidia/cuda:12.6.3-base-ubuntu24.04 nvidia-smi
```

容器内也应显示显卡。如果失败，先排查 [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)，不要靠重装显卡驱动碰运气。

社区训练控制器可能没有显式传 `--gpus all`，本实践还使用默认 NVIDIA runtime。**只在新机、没有训练任务时**配置；若已经是 `nvidia` 则跳过：

```bash
docker info --format '{{.DefaultRuntime}}'
command -v nvidia-ctk
```

`nvidia-ctk` 存在且当前 runtime 不是 `nvidia` 时，先备份已有配置，再配置并验证：

```bash
if [ -f /etc/docker/daemon.json ]; then
  sudo cp -a /etc/docker/daemon.json "/etc/docker/daemon.json.bak.$(date +%Y%m%d-%H%M%S)"
fi
sudo nvidia-ctk runtime configure --runtime=docker --set-as-default
sudo dockerd --validate --config-file=/etc/docker/daemon.json
```

只有验证成功后再执行下块；重启 Docker 会影响已有容器，所以不适用于正在训练的机器。

```bash
sudo systemctl restart docker
docker run --rm -e NVIDIA_VISIBLE_DEVICES=all nvcr.io/nvidia/cuda:12.6.3-base-ubuntu24.04 nvidia-smi
```

## 4. 下载训练平台，安装 Python 依赖

在新机执行：

```bash
sudo apt-get update
sudo apt-get install -y git jq awscli python3-venv python3-pip
```

```bash
cd "$HOME"
git clone https://github.com/aws-deepracer-community/deepracer-for-cloud.git
cd deepracer-for-cloud
git rev-parse HEAD
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
```

保留 `git rev-parse HEAD` 的版本号用于复现。看到 `No broken requirements found` 再继续。下载后停顿可能是解析下一个包或安装过程；没有新输出不等于卡死，不要同时开第二个安装进程。

## 5. 仅首次初始化

这是**新机单节点 Compose 示例**；已使用 Swarm 的旧机器不要照此切换模式。初始化脚本会生成/覆盖配置，因此不要在现有项目上重跑。

```bash
cd "$HOME/deepracer-for-cloud"
source .venv/bin/activate
bash bin/init.sh -a gpu -c local -s compose
```

这里 `local` 指用本机 MinIO 存储，不是说必须在自己的笔记本训练。初始化可能下载大型镜像。必须查看完整输出：结尾打印时间或出现 `DONE` 并不能单独证明全部镜像都拉取成功。

```bash
grep -E '^DR_(DOCKER_STYLE|SIMAPP_SOURCE|SIMAPP_VERSION|LOCAL_S3_PROFILE)=' system.env
docker image ls
```

确认镜像齐全、模式正确。镜像下载失败时按第 10 步判断；本仓库不承诺任何公共加速站可用。

本指南使用本机摄像头服务而非 AWS Kinesis 视频服务。首次激活前打开 `system.env`，将已有的 `DR_CAMERA_KVS_ENABLE` 项设为 `False`；单机入门将已有的 `DR_WORKERS` 项设为 `1`。保留其他配置，不添加重复键。检查 MinIO 和仿真服务的端口映射：上游版本可能默认监听所有地址，公网隔离未确认前不要放行相应云防火墙端口。

```bash
nano system.env
```

## 6. 首次训练：先跑默认配置

```bash
cd "$HOME/deepracer-for-cloud"
source .venv/bin/activate
source bin/activate.sh
```

激活环境可能启动 MinIO，但还不是开始训练。用编辑器打开 `run.env`，只在新机更改以下项目；保留其他默认项：

```bash
cp -a run.env "run.env.bak.$(date +%Y%m%d-%H%M%S)"
nano run.env
```

- `DR_WORLD_NAME=reinvent_base`：re:Invent 2018。
- `DR_TRAIN_REVERSE_DIRECTION=False`：核对比赛要求的方向，不能只凭赛道名称判断。
- `DR_LOCAL_S3_MODEL_PREFIX=my-first-model-001`：取一个未使用过的独立名字。
- 初次使用保持默认奖励/动作/超参数，等基本流程跑通再尝试本仓库实验配置。

在 nano 中 `Ctrl+O`、回车保存，`Ctrl+X` 退出。不要把 `system.env` 或 AWS 凭据发到公开仓库。

```bash
dr-upload-custom-files
```

检查自动关机时间、配置上传和剩余磁盘，确认要开始计费训练后，**单独执行**：

```bash
dr-start-training -q
```

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}'
```

出现容器不等于已经学会驾驶；还要确认训练回合增长、评估和 checkpoint 写入。不要为了绕过模型名已存在而加 `-w`，它会清空目标模型目录。

## 7. 装上本仓库的奖励曲线看板

另开一个服务器终端；不要覆盖上游训练仓库：

```bash
cd "$HOME"
git clone https://github.com/CsOH-Lawrence/deepracer-project.git
cd deepracer-project/metrics-dashboard
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest -v test_server.py
```

下行模型名必须与第 6 步一致。`minio` profile、endpoint 和 bucket 要与上游实际配置一致；使用同一用户才能读到对应的私有 profile。以下命令在前台提供页面，保持该终端运行：

```bash
.venv/bin/python server.py --profile minio --endpoint http://127.0.0.1:9000 --bucket bucket --model-prefix my-first-model-001 --port 3000
```

在**自己电脑的终端**执行，先将 `USER`、`YOUR_SERVER` 换成真实 SSH 用户和主机，并核对主机密钥：

```bash
ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=20 -L 127.0.0.1:13791:127.0.0.1:3000 USER@YOUR_SERVER
```

浏览器访问 <http://127.0.0.1:13791/>。关闭隧道窗口后页面会失联，但不会因此停止云端训练。

摄像头另查：在服务器运行 `docker ps --format 'table {{.Names}}\t{{.Ports}}'`，找到当前 robomaker 容器，再运行 `docker port 实际容器名`。确认容器 8080 对应的**主机端口**后，在本机另开隧道，将 `CAMERA_PORT` 替换为实际数字：

```bash
ssh -N -T -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:CAMERA_PORT USER@YOUR_SERVER
```

打开 <http://127.0.0.1:18080/stream_viewer?topic=/racecar/main_camera/zed/rgb/image_rect_color>。不同模型/并行仿真可能使用不同端口，不要默认每次都是 8080。

这些服务应限制在 loopback 或可信网络。不要直接放开看板、摄像头、MinIO、Docker 或 Swarm 管理端口给公网；Docker 发布端口的隔离需要单独检查，不能仅凭操作系统防火墙就认定安全。

## 8. 旧机器重新开机后怎么续训

**不要执行第 4～6 步初始化，也不要创建同名训练任务。**

```bash
cd "$HOME/deepracer-for-cloud"
docker info --format 'Runtime: {{.DefaultRuntime}}; Swarm: {{.Swarm.LocalNodeState}}'
nvidia-smi -L
df -h /
docker ps -a --format 'table {{.Names}}\t{{.Status}}'
grep -E '^DR_(WORLD_NAME|LOCAL_S3_MODEL_PREFIX|LOCAL_S3_PRETRAINED|LOCAL_S3_CUSTOM_FILES_PREFIX)=' run.env
```

先查清已有容器是否还活着、模型存储是否可读、最后及最佳 checkpoint 是什么，再选择原有进程恢复或创建**新的续训前缀**。不同版本操作可能不同，不提供一个可以盲贴到所有旧模型上的“万能续训命令”。可以把已脱敏输出交给 AI，要求“只续训，不改奖励/速度，保留来源模型，先核对 checkpoint，不使用清空参数”。

本地看板/摄像头隧道和日志接收进程在电脑重启后需重新打开，详见 [日志同步说明](../log-sync/README.md)。模型变更时同步修改接收配置，避免把不同模型混到一个日志目录。

## 9. 试用进阶奖励函数

先保留默认训练结果。本仓库 `custom_files/speed_2018_pace_v3` 内的三个文件需**成套**使用：奖励函数、动作空间、超参数。先在本仓库根目录执行测试：

```bash
python3 -m unittest discover -s reward_tests -p 'test_*.py' -v
```

然后在新实验中配置独立模型前缀和对应的 S3 自定义文件路径，确认上传后再启动。不要直接覆盖原模型。离散动作索引、数量或语义变化可能影响权重迁移；把速度整体改高也需要重新评估，而不是原模型立刻变快。

奖励更高不一定跑得更快。统计圈速只用 `Lap complete` 且进度 100% 的**评估完整圈**，同时报告完整圈数/总试次数、平均完成率和完整圈平均耗时。单次最快不是稳定成绩。

## 10. 常见报错速查

| 现象 | 优先检查 |
| --- | --- |
| `unshare: operation not permitted` | 宿主环境权限，不是换镜像加速源就能解决；向供应商确认虚拟机和容器支持 |
| Docker socket `permission denied` | 组成员是否加入、是否重新登录；不要用 `chmod 666` |
| `TLS handshake timeout`、连接超时 | Docker 守护进程自身代理、网络与镜像仓库连通性；与终端代理不一定相同 |
| 镜像 `403` / 白名单拒绝 | 镜像站策略；匿名 token 能取得不代表镜像有访问许可 |
| 某一层 `not found` | 镜像代理缺层或缓存异常；下载过部分层不代表整镜像完整 |
| `Selected path ... exists` | 保护机制：不要加 `-w`，应核实旧模型并选正确续训方式 |
| Compose 提示 `version is obsolete` | 通常是兼容性警告，不等于训练失败；继续查实际容器日志 |
| Step 很多但没完成圈 | Step 是采样累计，不代表训练完成；分开看训练与评估 |
| 网页失联 | 查 SSH 隧道、远端服务和真实端口，不要立即重启训练 |
| 平台 `226604` 资源不足 | 等待已有实例的资源，不是代码问题；不要重建/释放原机器 |

## 可以直接给 AI 的提示词

> 我想在云 GPU 虚拟机部署 DeepRacer。请按环境检查、Docker、GPU 容器、训练平台、看板的顺序逐步验收。我会给完整命令和报错。不要清理模型、不要重装已正常工作的驱动、不要开放公网管理端口。开始训练前先等我设好自动关机。新实验使用独立模型名，并解释改了什么、怎么测试、如何回滚。
