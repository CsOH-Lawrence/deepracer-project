# 学校 DeepRacer CPU 试点：部署入口、权限与风险

适用目标：Intel x86_64、32 vCPU、32 GB 内存的超融合平台**独立 Ubuntu 22.04 虚拟机**，校内访问。硬盘容量由学校安排，但仍需保留可用空间检查和日志/模型配额，避免耗尽共享存储。

## 先明确交付范围

本次已经提供：CPU 一键部署入口、安装前检查、固定版本训练平台、本地 MinIO、只读奖励曲线看板，以及权限/风险说明。默认不启动训练。

**尚未提供：20–30 名学生的自助账号、权限隔离、训练任务队列、教师管理界面，以及不可信奖励函数代码的安全执行平台。** 不能仅凭本次安装成功就开放全班登录训练。第一阶段仅由管理员/教师测试可信代码，实测一个任务的速度、内存和 CPU 摄像头表现；多人平台需另行开发并验收。

脚本通过 20 项本地测试（含模拟安装流程）及两个入口的 Bash 语法检查，**未在学校虚机或另一台全新 CPU 虚机完成端到端实装验证**。模拟测试不实际运行 apt、Docker、systemd 或训练。不承诺网络、镜像、Docker 或软件渲染一定兼容。

## 建议老师安排的环境

- 新建一台专用 Ubuntu 22.04 x86_64 虚机；不要在学生数据库所在操作系统内直接安装。可以使用同一超融合平台，但须由管理员隔离 VM、存储权限和资源配额。
- 给专用部署账号提供 SSH/控制台与 sudo 权限，学生不获得这些权限。
- 外网仅用于安装：需要访问 GitHub、Ubuntu 软件源、Docker 官方 apt 源（新装 Docker 时）、PyPI 与镜像仓库；不能访问时可由管理员安排经审查的离线包/内部仓库。不自动使用第三方镜像代理或关闭 TLS 校验。
- 保留校园内网访问方式。该版本看板只监听本机 loopback，默认使用 SSH 隧道验收；不会自动放行校园网或公网端口。学生正式访问入口需在登录系统完成后另行发布。
- 安装前做虚机快照/备份，确认快照是否覆盖挂载磁盘；安排资源、网络维护窗口和管理员回退流程。

“学校有学生数据库、磁盘很大”不能作为安全保证。训练镜像运行 Python 代码并消耗 CPU/内存，Docker 会创建网络，必须与业务数据库隔离。

## 一键使用方法（管理员执行）

若 Ubuntu 没有 `git`，先安装；有则跳过：

```bash
sudo apt-get update
sudo apt-get install -y git
```

复制以下三行到**学校 Ubuntu 专用虚机**，不要复制到学生 Windows 电脑：

```bash
git clone https://github.com/CsOH-Lawrence/deepracer-project.git
cd deepracer-project
bash deploy-school-cpu.sh --install-docker
```

流程说明：

1. 未安装 Docker 时，先检查系统、旧运行时数据/软件包和常见数据库迹象，然后说明额外权限；要求管理员输入 `DEDICATED_VM`、`INSTALL_DOCKER`。存在旧运行时数据或冲突软件包时退出，不自动卸载替换。
2. 经确认后使用 Docker 官方 apt 仓库和签名校验安装 Docker/Compose，启动 Docker，并将专用部署账号加入 docker 组。以该账号的新进程继续项目安装。现有 Docker 不自动升级/重装，已有但无访问权限时需管理员自行处理。
3. 项目检查通过后，再要求输入 `DEDICATED_VM`、`DEPLOY` 确认项目依赖、网络与看板服务安装。没有 NVIDIA 依赖，不下载 GPU 测试镜像。
4. 固定上游版本，准备 CPU 镜像和默认 re:Invent 2018 训练配置，启动本地 MinIO 与只读看板，验证自定义文件与指标 API。
5. **只显示后续训练命令，不自动启动训练**。教师确认训练时段与资源监测后再单独启动第一个测试任务。

已有 Docker/Compose 并且部署账号有 Docker 权限时，可以不带 `--install-docker`。仅做只读检查：

```bash
bash deploy-school-cpu.sh --check
```

只读检查不会安装软件、拉取镜像、写配置或启动服务。缺少先决条件时会报错退出，而不是显示“已部署”。已存在 `~/deepracer-for-cloud`、任何容器、现有训练网络、同名看板服务或端口冲突时停止；包括失败后的半成品目录，不自动删除后重来。

若目录已经存在，不要盲目 `git clone` 或删除：由管理员确认它是下载仓库还是已安装训练环境，再决定更新或恢复。不要在学校脚本中使用之前 GPU 单用户的启动命令代替 CPU 入口。

## 需要老师批准的权限

| 权限/变更 | 用途与边界 |
| --- | --- |
| 专用部署账号的 sudo | 安装 apt 依赖、创建/启用看板 systemd 服务；可选安装 Docker |
| Docker 管理权限 | 拉镜像、建网络、启停训练基础容器；接近主机管理员权限，只给管理员/可信部署账号 |
| 加入 docker 组（可选 Docker 准备步骤） | 持久权限变更，安装前须明确同意；不是普通网页查看权限 |
| 外网下载 | 下载固定上游源码、依赖及镜像；依赖包/镜像供应链仍需学校审查，固定源码不等于全部依赖固定 |
| 用户目录及私有 `.aws` profile | 训练代码、模型、日志和本地 MinIO 凭据；凭据不入 GitHub，不向学生分享 |
| Docker 网络、systemd 服务 | 建 `sagemaker-local` 网络，启用 MinIO/看板开机恢复；不会自动恢复/启动训练 |

脚本不执行 DNS、ufw 或校级防火墙修改，**但 Docker 自身可能修改 iptables/转发规则**，因此不能解释成“完全不影响网络”。公网端口不自动开放，内网服务也必须认证和授权后才开放。

## 风险与限制（重要）

1. **数据安全**：数据库探测只覆盖部分常见进程/端口，不能证明机器无数据库或无敏感数据；独立虚机及备份必须由管理员确认。脚本不读取学生数据库内容。检测到数据库时不要通过停库绕过检查，应另建专用虚机。
2. **资源争用**：32 核是虚机配额，不保证独占物理核心。初期仅测试一个训练任务，不承诺 20–30 人同时训练。CPU 镜像和软件渲染性能必须实测。
3. **资源限制范围**：CPU 模式对新建外层 coach/robomaker 容器设置每容器 8 CPU / 8 GiB，对 MinIO 设置 2 CPU / 2 GiB。这不是全任务预算：SageMaker 另建的训练容器**尚无本脚本覆盖的总资源上限**。需要学校在虚机层限制资源；正式开放前必须完成整个任务的限额与队列控制。
4. **代码执行**：学生的奖励函数是可执行 Python。仅分文件夹、加登录框或检查 Python 语法都不能当安全沙箱。未完成隔离前只运行老师审查过的可信代码，不收集全班任意代码执行。
5. **供应链/网络**：镜像很大，下载失败/仓库限流可能发生；上游固定 commit，MinIO `latest` 和 Python 依赖仍会变化。脚本失败会保留半成品，不自动回滚或清理数据。
6. **凭据**：MinIO profile、模型文件、日志和截图均可能含敏感信息。学校数据库凭据绝不能拿来给训练使用。安装程序不索要数据库密码，不创建学生网站密码。
7. **服务持久化**：MinIO/看板可随开机恢复，不代表训练自动恢复；部署成功不等于训练结果正确。停止训练、停止看板、停机是不同操作。

## 首次验收与回退

- 管理员检查 Docker 网络和 `docker ps` 端口：看板 3000、MinIO 9000/9001、后续摄像头只应本机可达。测试内网及公网均不能绕过预期隔离，注意 Docker 端口发布可能绕过部分主机防火墙规则。
- 用管理员自己的 SSH 隧道查看看板，执行一次短训练，记录 CPU、可用内存、磁盘增长、完整评估圈和摄像头表现。**暂不让全班同时提交训练**。
- 发生兼容报错先停止，不改系统安全设置“强行跑通”，不重装驱动、不清理其他容器、不使用 `docker system prune` 或模型清空参数。
- 看板可用 `sudo systemctl disable --now drfc-metrics-dashboard.service` 停用；这不停止 MinIO 或训练。安装/运行前由管理员约定完整停训和恢复方式。
- 程序没有自动卸载入口：管理员依据安装清单与快照回退。回退整个虚机前确认没有新增需要保留的模型；不要在仍承载其他业务的虚机用恢复快照解决问题。

- [ ] 同意上述 sudo / Docker / 软件源 / 网络变化，仅限专用部署账号。
- [ ] 校内访问，尚不对学生开放未完成的多人训练功能。
- [ ] 先做单任务 CPU 试点，实测后再审批并发、时长、配额和代码隔离。
