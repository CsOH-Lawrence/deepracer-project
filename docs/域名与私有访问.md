# 域名访问：先登录，再看训练

本文为接入设计及验收清单，**尚未在本项目云主机实施**，没有创建真实 DNS、网站账号、证书或公网入口。教程统一使用 `example.com`，实际操作时才替换为拥有的域名。

## 分工

| 地址 | 作用 |
| --- | --- |
| `https://train.example.com` | 登录后访问只读奖励曲线看板 |
| `https://camera.example.com/stream_viewer?topic=/racecar/main_camera/zed/rgb/image_rect_color` | 登录后观看模拟摄像头 |
| 原主域名和其他子域名 | 保持原用途，不覆盖 |

DNS 负责找到入口，反向代理再按主机名转到不同的本机服务；DNS 的 A 记录不能填写 `IP:端口`。仅添加 A 记录不会自动得到 HTTPS、登录或代理。

## 阿里云 DNS 保留不动的方案

1. 在域名详情进入“域名解析”，不是“DNS修改”。先查看并备份已有记录，不更改 NS、邮件记录、主域名、泛解析或现有同名记录。
2. 服务器开机后核实公网 IP、看板 loopback 3000 和摄像头的实际端口；检查已有 Web 服务、证书和平台域名接入要求。若已存在同名 `train` / `camera` 记录，停止并确认用途。
3. 在入口准备好、用户确认后添加两条 A 记录，主机记录分别为 `train` 和 `camera`，记录值为当前入口 IPv4。域名自身不需要从阿里云转出。
4. 用可信证书配置 HTTPS，在代理层给两站都加登录校验，**包括看板 API、摄像头流地址，不只是首页**。HTTP 只跳转 HTTPS 或用于必要的证书验证，不在明文 HTTP 中收密码。
5. 为自己与老师分别创建查看账号，使用不同强密码；由用户在安全终端交互输入，不把密码写到命令参数、聊天示例、GitHub 或截图。网站账号与 SSH/MinIO 账号完全分开。
6. 反向代理只连接 `127.0.0.1:3000` 和实际摄像头端口，训练服务本身保持私有。摄像头是长连接，需要禁用代理响应缓冲、设置合适的读取超时并实测延迟。
7. 不开放 Docker API、Swarm、MinIO、VNC 等管理接口。不把“知道域名”当作授权，也不允许从原始 IP/端口绕过登录。Docker 端口映射和云侧防火墙要一起核对。

可选实现为 **Nginx + HTTPS + HTTP Basic Authentication**。浏览器会弹出用户名和密码框，这是简单登录方式，不是精美的账号管理页面；知道密码即可访问，需要妥善分享和撤销。不具备逐帧权限收回能力，注销/撤销后还应测试并处理已有长连接。

服务器的开机、停机、IP 变化、训练容器重建会影响入口。域名不会自动开机或让停止的摄像头继续直播；查看本身也需要服务器在线计费。

## 不想开放入站 Web 端口时

可以考虑 Cloudflare Tunnel + Access：由服务器主动连出，再用身份策略保护域名入口。通常需要合适的 Cloudflare DNS 接入方式及账号设置，**不是只在阿里云随便加一条 CNAME 就一定完成**。先确认原有网站/邮件记录影响、服务条款、网络连通性及视频流使用要求，再决定是否使用；不默认转移 NS，不承诺大陆访问速度或免费额度。

## 上线验收（全部通过才给老师链接）

- 在未登录的无痕窗口访问主页、`/api/metrics` 和摄像头流，都不能取得内容；错误账号被拒绝。
- HTTPS 证书有效，浏览器没有证书警告，不要求用户关闭安全检查。
- 正确账号能看图表刷新和实际摄像头画面；另一个站也受到保护。
- 从外部网络尝试原始服务端口，不能绕过代理；注意 IPv4 与 IPv6 的配置一致性。
- 看板模型名、数据更新时间、当前摄像头对应模型正确；历史指标不冒充在线训练。
- 摄像头连续播放数分钟，检查缓冲、超时和登录会话行为；页面不得嵌入绕过保护的公开流链接。
- 服务器重启后验证 Web 服务恢复、实际摄像头端口是否变化，且不会为展示网页自动启动训练。
- 撤销老师账号后验证新请求被拒绝，并检查是否还有未关闭的既有视频连接。

当前只有 DNS 管理权限或只有“域名已实名认证”都不足以完成以上事项；上线还依赖服务器可用、证书、代理配置、登录保护和平台接入条件。
